# Security Policy

## Reporting a vulnerability

If you discover a security issue in Quiver, please do not open a public issue.

Please report it privately by emailing the maintainer or by using the repository's private security contact if one is configured.

Please include:

- the affected component or file
- a description of the issue
- reproduction steps
- any required environment details
- the severity and impact you believe it has

## Disclosure expectations

We ask that vulnerable reports be handled responsibly and that you allow a reasonable time for the maintainers to investigate and fix the issue before public disclosure.

## Safe handling guidance

- never commit credentials, tokens, AWS keys, or local secrets to the repository
- never include production secrets in issues or pull requests
- prefer using local dev credentials or safe sample values in examples

## Supported versions

This project is currently in active development. Security fixes are prioritized for the current main branch and the latest release tag.
